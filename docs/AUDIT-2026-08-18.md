## Performance medida/identificada

- Cuello confirmado: `server/state.js` hacia `writeFileSync` del JSON completo en cada UPDATE/TAKE y ejecutaba copia/listado/borrado sincrono para backups. Un input envia un UPDATE tras 350 ms; la E/S bloqueaba el mismo hilo que atiende WebSocket. Se reemplazo por cola asincrona, coalescing de 500 ms, escritura atomica y la misma rotacion limitada de cinco snapshots cada diez minutos fuera del camino sincrono.
- Cuello confirmado menor: cada lectura del catalogo releia sincronicamente `team-abbreviations.json`. Ahora las abreviaturas se hidratan una vez y viven en memoria; `assets/crests/` se sigue listando por pedido para conservar el contrato de detectar escudos nuevos sin restart. Son 14 escudos actuales, por lo que no se justifico cachear esa carpeta.
- Escritura manual de planteles: era atomica pero sincrona; se unifico en la cola asincrona. No era un hot path, pero era una segunda fuente de persistencia incompatible.
- Trafico: el Master ya agrupa tipeo con 350 ms y el servidor transmite un `MODULE_UPDATE` del modulo afectado, no snapshots globales. No se encontro envio por cada tick de reloj.
- Timers: Program crea tickers de 500 ms solo para modulos `live` en `ON` y los detiene en `OUT`; limpia timers/intervalos de contenido. Los paneles de reloj devuelven cleanup al cambiar de panel. No se demostro un timer huerfano que justificara cambios.
- DOM: varios paneles reconstruyen su arbol en cambios estructurales (tabs, filas, equipos), pero los inputs normales no fuerzan un render completo general. No se aplico un refactor de UI sin perfil de navegador que demuestre beneficio.
- Media: no se toco `program/js/alpha-video.js`. El pipeline existente evita remontar video/canvas en UPDATE y libera recursos en OUT.
- Assets runtime: `assets/` contiene 58 archivos y aproximadamente 16,9 MB. No se encontro una duplicacion activa dentro de `assets/` que justificara borrar automaticamente.
- Muestra local con Marcador al aire: el proceso servidor consumio 0,00 s de CPU en una ventana de 2 s, 57,8 MB de working set y 13 threads. Master cambio entre Marcador/Resultados y Program completo `TAKE -> UPDATE -> OUT` sin warnings/errores. Esta muestra no reemplaza un perfil largo del renderer del navegador con varias capas de video simultaneas.
